# 一句话进销存 · 批次与进阶进销存设计（v1 草案）

> 依据：需求方 2026-11-20 提出的问题（批次、分批成本、FIFO/指定批次、还有哪些进销存问题）。
> 对齐 `product-decisions-v2 (1).md` 的 UX 口径与 `index-v2/index.html` 原型的现有字段。
> **本轮只改原型，不改业务代码**；原型经确认后再进入代码。
> 数据真实性：文中所有价格、数量、天数、阈值均为示例或「假设，需核实」，未引用任何竞品或外部事实。

---

## 0. 一句话结论

1. **批次是「能力」，不是默认流程**：默认关、按货开、用到时再提示一次，绝大多数老板永远看不到它。
2. **计价方法系统定死，不让老板选**：无批次货用「移动加权平均」，开了批次的货用「FIFO 先进先出」，有保质期的货用「FEFO 到期先出」。老板卖货时**永远不会被问「扣哪一批」**。
3. **只在老板主动说批次时才出卡**：「卖昨天进的可乐」这类口语命中后，才弹一张候选批次卡让点一下。
4. **盘点对批次透明**：盘点仍然只报「总数量」，60 秒连说体验不变；差额由系统按计价规则分摊回批次。
5. **毛利口径延续 v2**：缺进价的货（含某一批缺进价）不算进毛利，标黄进「待处理 · 要补」。

## 1. 批次管理是否必要（分层判断）

| 业态 | 是否需要批次 | 理由 |
|---|---|---|
| 便利店 / 水果摊 / 散卖（倒推为主） | 默认不需要 | 快进快出，毛利靠售价倒推；老板懒，批次是负担 |
| 批发档口 / 建材五金（逐笔为主） | 按需可选 | 同货不同进价常见，对账/毛利/退货溯源有价值，但非必需 |
| 有保质期的店（食品/生鲜） | 强烈需要（至少效期） | 临期/过期是硬需求，FEFO 是刚需 |

「需要的人能用、不需要的人不被打扰」——渐进启用四条：

1. **默认关**：批次是可选能力，不进主流程。
2. **按货开、不按店开**：只给需要批次的那几件货开。
3. **触发式开启**：老板第一次说出批次信息（「这批可乐进价三十八」「这批下月到期」）时提示一次「要不要给这件货记批次？」，可拒绝。
4. **入口放深处**：货品详情 → 这件货 →「批次设置（高级）」，普通老板看不到。

- 优先级：**批次作为可选能力（默认关、按货开启）= 必须做**；全店强制批次 = 暂不做（违反极简）。
- 假设，需核实：「便利店不需要批次」是假设；触发式开启的接受度需真机验证；各业态占比需核实。

## 2. 批次数据结构

| 字段 | 说明 | 录入方式 | 必填级别 |
|---|---|---|---|
| batch_id | 批次号（日期+序号，如 1120-1），系统生成 | 系统 | 系统 |
| product_id | 所属货品 | 进货卡已有 | 必须现在填 |
| in_date | 进货日期 | 默认今天，可语音改 | 必须（有默认） |
| cost | 该批进价 | 语音 / 黄色空格补 | 可后补（黄） |
| qty_in | 进货数量 | 语音 | 必须现在填（红） |
| qty_left | 剩余数量（派生：进 − 出 − 退 − 损） | 系统算 | 系统 |
| supplier | 供应商 | 默认不出现；赊账时带出 | 不用补 |
| expiry_date | 到期日（仅效期货） | 语音 / 黄色空格补 | 可后补（黄） |
| note | 备注 / 票号 | 不出现 | 不用补 |

关键设计：

- **批次号不让老板起**（老板记不住编号），语音里用「这批 / 昨天进的 / 老赵那批」口语锚点，系统内部映射。
- **进价沿用现有机制**：黄色空格 →「待处理 · 要补」→ 补完算进利润，与 v2 文档「苹果缺进价」完全一致。
- **qty_left 靠盘点对平**：复用 v2 对账公式，不另起一套。

- 优先级：核心六字段 = 必须做；`expiry_date` = 效期店必须、其他可选；产地/等级/条码批号 = 暂不做。
- 假设，需核实：批次号规则是否契合对账习惯；「下月 15 号到期」的解析准确率。

## 3. 出库计价方法（老板问题 3/4 的核心）

**最关键约束：老板卖货时绝不被问「扣哪一批」。计价是后台默认规则，语音层零打扰。**

| 方法 | 适用场景 | 优点 | 缺点 | 语音友好度 |
|---|---|---|---|---|
| FIFO 先进先出 | 有保质期 / 怕积压 / 批发 | 顺直觉，毛利可信 | 需记批次顺序 | 高（后台自动） |
| 移动加权平均 | 便利店 / 散卖 / 快进快出 | 单一成本，不追问批次，毛利平稳 | 不反映单批真实进价，与效期无关 | 最高（完全无感） |
| 指定批次 | 批发，客户指定某批 | 精确 | 每次要选批，打扰 | 低（例外才用） |
| 个别计价 | 大件 / 高值 / 建材 | 最精确可溯源 | 录入负担最重 | 最低 |

主推策略：

- **无批次货默认「移动加权平均」**：与现有单一 `cost` 字段天然兼容（≈把多批进价平均成一个 cost），改造最小、完全无感。
- **开了批次的货默认「FIFO 先进先出」**：符合「先买的先卖」直觉，效期店平滑过渡到 FEFO。
- **不向老板暴露「计价方法」术语**：默认规则系统定死（沿用 v2「必补项由系统定死」口径）。仅在「我的 → 批次设置（高级）」藏一个开关。
- **「指定批次」只作例外**：不报批次号，用口语锚点——「卖昨天进的可乐」「卖老赵那批螺丝」「先把快到期的出了」。命中后出一张轻卡列 2–3 个候选批次让点（复用红色空格 + opts 样式），默认高亮系统建议批。

- 优先级：移动加权平均（默认）+ FIFO（批次货默认）= 必须做；指定批次 = 可选做；FEFO = 效期店必须；个别计价 = 暂不做。
- 假设，需核实：「老板不懂也不关心计价方法」是假设；口语锚点识别准确率；老板是否担心平均成本导致毛利不准。

## 4. 成本计算与毛利

| 指标 | 公式 | 说明（假设，需核实） |
|---|---|---|
| 批次库存金额 | `qty_left × batch.cost` | 有批次的货 |
| 单品库存金额 | `Σ(各批 qty_left × cost)` | 批次货；非批次货 = `stock × cost` |
| COGS（销售成本） | 卖出数量 × 结转成本（按计价方法取对应批 cost 或平均 cost） | 每笔卖出结转 |
| 毛利 | 销售额 − COGS | 缺进价的货不计入（沿用 v2） |
| 缺进价衔接 | 批次进价没补 → 该批 COGS 无法算 → 对应卖出不计毛利、标黄进「要补」 | 与「苹果缺进价」完全一致 |

与 v2 口径衔接：

- 提示语从「毛利没算：苹果（缺进价）」扩展为「毛利没算：苹果、可乐（有一批没记进价）」。
- **倒推店**：卖出靠盘点差额按售价估出，无逐笔 COGS → 毛利只能用「估算卖出量 × 当前平均 cost」粗算，**必须标注「估算」**，不能假装精确。
- **逐笔店**：每笔有明确数量与结转成本，毛利较准。
- 改单 / 撤单：复用 v2「反做原单 + 新建更正单」，成本同步冲回重算。

- 优先级：基础 COGS + 毛利（含缺进价跳过）+ 缺进价衔接 + 倒推店标注「估算」= 必须做；批次级毛利报表、追溯重算 = 可选做。
- 假设，需核实：毛利数值均为示例；倒推店估算误差可接受度；老板是否理解「估算毛利」。

## 5. 其他必须综合考虑的进销存问题

逐条给出：问题 / 对语音交互的影响 / 建议方案 / 优先级 / 需核实点。

| # | 问题 | 语音影响 | 建议方案 | 优先级 | 假设，需核实 |
|---|---|---|---|---|---|
| 1 | 负库存 / 超卖 | 不该硬拦（老板懒会烦），但要提示 | 允许负库存，出轻提示「可乐账上 2 箱卖了 3 箱，是不是漏进？」进待处理核对，不阻断；批次卖空按默认计价自动转下一批 | 必须做 | 提示阈值 |
| 2 | 采购退货 vs 销售退货 | 「退红牛」方向有歧义 | 退货卡加「方向」格（客户退回 / 退给供应商），按上下文猜，猜错用红色空格点选；采购退货按原批次 cost 冲回成本与库存 | 必须做 | 默认方向猜测准确率 |
| 3 | 盘点与批次 | 绝不能让老板逐批报数（破坏 60 秒连说） | 盘点仍盘「总数量」，现有盘点模式零改动；差额按计价方法分摊回批次（FIFO 从最早批扣/补）；批次对盘点透明 | 必须做 | 差额分摊口径 |
| 4 | 拆箱换算与批次 | 沿用「第一次问一箱几个」，不重复问 | 批次统一存最小单位（瓶）余量，进货 ×conv 入库、卖货按瓶扣；`batch.cost` 以采购单位记，自动折算每瓶成本 | 必须做 | 多层换算需求 |
| 5 | 损耗 / 报损 | 「坏了 3 瓶 / 过期扔了」应能一句话记 | 加一种流「报损」；批次货按 FEFO/FIFO 扣批次；单列「损耗」科目（便于看真实毛利），进对账公式的「记下的损耗」项 | 可选做 | 是否单列科目 |
| 6 | 保质期临期预警 | 不进语音，是被动提醒 | 效期批到期前 N 天在货品页标「临期」小标（复用「快没了」样式）；首页顶部一条「有 2 样快到期」轻提示 | 可选做（效期店必须） | N 天阈值 |
| 7 | 供应商管理 | 不该在进货卡强问供应商 | 轻量档案（名字/电话/欠我我欠），从赊账往来自动沉淀；批次 supplier 可空 | 可选做 | 是否需要独立档案 |
| 8 | 价格历史 | 只读展示，不进语音 | 批次天然是价格历史，货品详情用时间线列「11-20 进 ¥35、11-15 进 ¥34」 | 可选做（批次启用后自然获得） | — |
| 9 | 库存预警阈值 | 「可乐下限设 10 箱」低频 | 沿用现有 `low` 字段，放货品详情可语音设；默认按 conv 推算（如 2 箱） | 可选做 | 默认阈值 |
| 10 | 单据反做 / 红冲留痕 | 保持改单卡，无新增打扰 | 批次成本随反做冲回重算；旧值划掉留痕、不物理删除；批次余量同步恢复 | 必须做 | — |
| 11 | 期初建账 | 复用「开张盘点」60 秒连说 | 期初货默认建一个「期初批次」（日期=建账日，cost=盘点填的或待补），老板无感 | 必须做 | 是否需分批期初 |
| 12 | 多单位换算 | 守住「一箱几个」一层口径 | 保持一层（主单位 + 最小单位）；多层（件→包→根）暂不做 | 一层必须做（已有）；多层暂不做 | 建材多层需求强度 |
| 13 | 赊账与批次 | 赊账卡不该问批次 | 赊账只记人欠多少，确认时按默认计价扣库存批次，与普通卖出一致；不锁批次 | 赊账扣批次必须做；锁批次暂不做 | — |
| 14 | 成本调整 / 估价入库补差价 | 复用「待处理 · 要补」补进价 | 补进价 = 更新批次 cost 并追溯重算已结转 COGS/毛利（或仅从补价时点起算，口径需定）；「那批可乐进价改 38」触发改单卡 | 补进价必须做；追溯/补差价可选 | 追溯起算口径 |
| 15 | 赠品 / 搭售 | 「送了一瓶」不该报错 | 默认识别为出库但不计收入（归入报损/其他出库），先做到识别不报错 | 暂不做 | 是否扣库存 |
| 16 | FEFO 效期先出 | 后台自动无感；「把快到期的出了」是自然表达 | 对开了效期的货，默认计价由 FIFO 切 FEFO（按 expiry_date 升序扣批），与指定批次口语锚点衔接 | 效期店必须；其他暂不做 | 效期解析准确率 |

## 7. 七个「待核实」逐条拍板（2026-11-20 定稿）

> 需求方明确：这 7 条由产品侧决定，不留给老板。以下为定稿方案。凡数值仍标「假设，需核实」，但**决策本身已定，不再反问用户**。

### 7.1 各业态需求强度 → 决策：**不按业态判断，按货判断（按货开启 + 触发式 + 手动入口）**

否决「登录时选业态 / 分业态预设」。理由：业态是开发者脑内的分类，老板不会准确自我归类；同一家店不同货的需求也不同（可乐要批次、纸巾不要），按店归类必然错。

定稿：

- 登录**只问 v2 已定的一个问题**：「主要零售还是批发？」——它只决定**记账方式**（逐笔 / 盘点倒推），与批次无关。
- 批次开关**按货**：默认全关 → 老板第一次说出批次信息（「这批进价 38」「下月到期」）时提示一次「这件货要记批次吗？」→ 随时可在货品详情手动开。
- 不设「业态 → 默认批次策略」的映射表。

### 7.2 口语锚点识别 → 决策：**两段链路各管各的，规则优先、AI 兜底（不新增能力）**

必须分清两段完全不同的链路（这是关键概念澄清）：

| 段 | 做什么 | 谁负责 | 花钱吗 |
|---|---|---|---|
| 第一段：语音转文字（ASR） | 声音 →「卖昨天进的可乐」这段文字 | 同声传译插件为主；听错字/方言时走适配层切付费 ASR（v2 §18 已有方案） | 插件免费有配额（250 条/分、3 万条/天，全 AppID 共用，**需核实**）；付费 ASR 按量 |
| 第二段：听懂意思（NLU） | 文字 →「卖 / 可乐 / 2 箱 / 昨天那批」 | 规则层优先，拆不了才大模型 | 规则 0 元；大模型按 v2 §2.2「智能理解次数」计费 |

「昨天进的 / 老赵那批 / 快到期的」属于**第二段**，和用什么语音识别服务无关——文字已经转出来了，问题是怎么理解。

定稿规则层映射（0 元）：

- 「昨天进的 / 上周那批」→ 按进货日期匹配最近批次；
- 「老赵那批」→ 按供应商匹配（供应商来自说法本）；
- 「快到期的」→ 按 expiry_date 升序取第一批（FEFO）。

规则拆不了的复杂指代才交大模型，算 1 次智能理解。**成本控制三件套**：规则层优先 + 只在大模型那一步计费 + 每店每日硬上限（v2 §2.3）。

### 7.3 到期日语音解析 → 决策：**日期归一化写成规则，AI 只兜底模糊说法**

- 「下月 15 号」「三天后到期」「月底」这类相对日期 → 规则层算出绝对日期（0 元，技术成熟）。
- 只有「这批大概月底吧」这种模糊说法才交大模型猜，猜出来仍出黄色空格让老板点确认。
- 语音把「15」听成「十伍」是第一段的问题，走 ASR 兜底，与日期规则无关。
- 需核实：中文相对日期口语的覆盖清单（内测收集）。

### 7.4 计价方法 → 决策：**写死，按货属性自动决定；不配置、不分行业、不给老板看术语**

| 货的属性 | 计价方法 | 理由 |
|---|---|---|
| 无批次 | 移动加权平均 | 中小企业主流；单一 cost 字段天然兼容，改造最小、完全无感 |
| 有批次、无到期日 | FIFO 先进先出 | 顺直觉，价格波动/批发场景更可信 |
| 有到期日 | FEFO 到期先出 | 避免过期损失，FIFO 的自然延伸 |

否决「可配置」和「分行业预设」：老板既不懂也不关心计价方法术语；行业判断会重新引入 7.1 已否决的业态分类负担；同一家店不同货需求不同，**按货属性比按业态更准**。沿用 v2「必补项由系统定死」口径。

- 老板永远看不到「计价方法」四个字；仅「我的 → 批次设置（高级）」里有一行**只读**说明。
- 依据（市面通用做法）：中小企业成本核算主流为移动加权平均，FIFO 用于有批次/保质期/价格波动大的商品；且**贵在长期一致，不能月月切换**（易失真）。
- 需核实：老板是否因平均成本导致毛利平滑而困惑（内测观察）。

### 7.5 各阈值与保质期录入 → 决策：**默认写死，保质期「有则录、无则不打扰」**

- **保质期/到期日**：作为「可后补的黄色空格」录入。绝大多数货没有保质期 → 默认不出现、不询问；有保质期的货在进货时说一句「这批下月 15 号到期」即可，没说就空着、不报警。用户确认「这类信息肯定要录入」——采用**有则录入、无则不打扰**的录入策略，而非全字段强制。
- **临期预警提前 N 天**：默认写死 **7 天**（假设，需核实），按货类预设（生鲜 3 天 / 食品 7 天 / 药品 30 天），老板不用配。
- **负库存**：允许，卖超出库时轻提示一次「是不是漏记了进货？」进待处理核对，**不做硬拦截**。
- **库存下限**：沿用 v2「快没了」，可语音设「可乐下限 10 箱」，不设就不提醒。

### 7.6 成本追溯重算 → 决策：**默认「未来适用、不追溯」，另给一个可选的高级重算按钮**

**市面通用做法（已核实，见 §7.8 来源）**：

1. 会计准则区分「会计政策变更」（追溯重述）与「会计估计变更」（未来适用）。补进价属于**新信息 → 估计变更 → 未来适用，不追溯**。
2. 暂估入库主流实务：按《企业会计制度》的重要性与简化原则，**已结转的发出成本不单独调整，差额随后续收发自行消化**；货已售出的调当期主营成本，跨年且金额重大才走以前年度损益调整。《小企业会计准则》**不要求追溯**。
3. 软件厂商（速达等）实务：票到红冲重做，差额按货的去向分流——在库调存货成本、已售调当期成本，只重算关联批次。

定稿（贴合极简 + 小企业定位）：

- **默认不追溯**：补进价后，从补录那一刻起，剩余库存按新进价算成本；**已卖掉的那部分毛利不改历史报表**（改了老板会懵，且与小企业准则一致）。
- 补录时提示一句：「已卖出的 8 瓶仍按旧进价算。」并给一个**高级按钮**「重算这批毛利」（默认不点，属于可选增强）。
- 跨年 / 金额巨大的追溯**不在本产品范围**（目标用户是小店、月度经营为主）。
- 需核实：重算按钮是否真的有人用；提示文案的措辞。

### 7.7 采购退货 vs 销售退货的方向 → 决策：**不猜方向，出卡时固定带一个二选一，默认按上下文高亮**

用大白话讲清问题：老板说「退了两箱红牛」，这句话有两种**完全相反**的意思——

- (a) **客户把货退回来了**：货 +2，钱退给客户，库存增加（销售退货）；
- (b) **我把货退给供货商了**：货 −2，供货商退我钱，库存减少（采购退货）。

系统光听这句话分不出来；**猜错的代价是库存和账全反**，比多问一句严重得多。

定稿：

- 出退货卡时**固定带一个「方向」格**（复用红色空格 / opts），两个大按钮「客户退回来」/「退给供货商」，老板点一下。
- 默认按上下文**高亮**一个（附近有进货记录 → 退给供货商；附近有卖货记录 → 客户退回来），但高亮≠确定，仍要点。
- 采购退货按**原批次 cost** 冲回成本与库存；销售退货按原价退回。
- 不追求「语音直接猜对方向」——这是不该省的一次点击。

### 7.8 本办法引用来源（公开资料，非本项目事实；平台/准则会变，需定期复核）

- 会计政策 vs 会计估计变更、追溯 vs 未来适用：正保会计网校、IAS 8 解读（digitalsalla / uaetaxcompliance）。
- 暂估入库差额处理与不追溯：百度百科「暂估入账」（引《企业会计制度》重要性原则）、共享会计师问答、速达软件实务。
- 中小企业计价方法选择（移动加权平均为主、FIFO 用于批次/效期/价格波动、贵在一致）：轻流、简道云、九数云等进销存实务文章。
