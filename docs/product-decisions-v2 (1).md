# 一句话进销存 · 交互口径 v2（评审回复）

> 依据：需求方 2026-11-20 对 19 条评审意见的回复。本文只管 UX/UI 和流程口径，以及它们对 AI 成本的影响。
> 平台能力、报价、配额都标了「需核实」，不能当成事实。

---

## 0. 定下来的总原则（一句话版）

1. **记账方式分两种，账只有一本。** 逐笔记和盘点倒推是两种记的方式，最后都落到同一套库存和流水上，靠盘点对平。
2. **能听清就直接记，听不清才出卡。** 每一笔都进「今日流水」，随时能看、能改、能撤。
3. **没有倒计时。** 卡片一直留着，直到老板确认、关掉，或者开始说下一句。
4. **系统只有一个「待处理」。** 要补的、没确认的都放这里，不再分五种。
5. **手机能做全部事情。** 电脑只是看得更全、改起来更快，不是必须有。
6. **钱的事只确认一次，用手点。** 不念出来，也不让老板说「确认」。

## 1. 两种记账方式 + 对账

### 1.1 两种方式是什么

| | 逐笔记 | 进货 + 盘点倒推 |
|---|---|---|
| 谁用 | 批发、档口、建材五金、有固定客户的 | 便利店、水果摊、零售为主的 |
| 记什么 | 进、卖、赊、退、收款，每一笔都说 | 只记**进货、赊账、退货、收款**；零散卖货不记，或者只说一句「今天收了 1286」 |
| 卖了多少从哪来 | 记下来的销售单 | 盘点时倒推：上次剩的 + 进的 − 赊出的 − 盘点数 |
| 首页重点 | 今日流水、欠款 | 进货、待盘点提醒、本周估算卖出 |

开店时问一句「你家主要是零售还是批发？」，决定默认方式。以后在「我的」里随时能改。**也可以混着用**：给熟客的批发单逐笔记，过路散客靠倒推。

### 1.2 对账：两种方式最后都靠盘点对平

两种方式背后是同一个算式：

```
账面应剩 = 上次盘点数 + 这期间进的 − 这期间记下的卖出 − 记下的损耗
差额     = 账面应剩 − 这次实盘数
```

每次盘点后出一张「对账结果」卡，差额怎么解释由老板点一下决定：

| 差额怎么来的 | 逐笔记的店，默认这样 | 盘点倒推的店，默认这样 |
|---|---|---|
| 少了（实盘 < 账面） | 默认当成「可能漏记的卖出」，同时给出「损耗」「盘错了」两个选项 | 默认算作「散卖」，按售价估一个卖出金额 |
| 多了（实盘 > 账面） | 「可能漏记了进货」，或「上次盘错了」 | 同左 |

界面写法：

```text
可乐  账上应剩 12 箱，你数的是 9 箱，少了 3 箱
( 散卖了 ✓ )  ( 坏了/丢了 )  ( 我数错了，重数 )
按售价估算：卖出 ¥105，赚 ¥21
```

**这就是你要的对账功能。** 对逐笔记的店来说，差额就是漏记报警，差得越多，说明越该多记；对倒推的店来说，差额本身就是销量。数据结构是同一套，只是差额的默认解释不同。

### 1.3 盘点怎么说：不要一件货按一次

盘点有专门的**盘点模式**，入口在货品页的「开始盘点」：

- 页面就是一张货品清单。每一行显示商品名、账上数量，再留一个空格给实盘数。
- 点一次说话，可以连着说一长串：「可乐九箱，雪碧五箱，红牛没了，矿泉水十五瓶」。系统边听边把数字填进对应的行，填过的行变色。
- 一次最多录 60 秒（逐笔记是 15 秒），中间停顿不会自动断。说完再点一下就结束。
- 没说到的行保持空着，不会当成 0。最后出一张整单对账卡，一次确认。
- 不想说话也行：点某一行，直接用数字键盘填。

**开张第一天**用的是同一个页面，叫「开张盘点」。货品是在说的过程中边说边建的，最后整单确认。

### 1.4 为什么盘点模式反而便宜

「商品 + 数字 + 单位」重复 N 遍，是最规整的句式，规则就能拆，**基本不用调用大模型**。只有遇到同名的货、没听过的叫法、「上次那个」这种指代，才交给模型去理解。所以说话时长放宽到 60 秒，对 AI 成本影响很小。真正花钱的是另一类：**说法复杂、规则拆不了**的句子。

## 2. 成本怎么控（回答「老板无限制用，我会不会亏」）

### 2.1 钱花在哪

| 环节 | 每次花多少 | 能不能控 |
|---|---|---|
| 语音转文字 | 看用哪家，见第 18 节；同声传译插件免费但有配额（需核实） | 靠限时长、去掉误触和闲聊 |
| 规则层（模板、词表） | 0 | 命中越多越省 |
| 大模型理解 | 按调用次数算，是主要成本（报价需核实） | **只有规则拆不了的句子才调用** |

### 2.2 计费口径：按「智能理解次数」，不按说话次数

| 句子类型 | 例子 | 算不算次数 |
|---|---|---|
| 规则能懂的标准说法 | 「进了两箱可乐一件三十五」「可乐九箱雪碧五箱」 | **不算，不限次** |
| 要调用大模型的 | 「上回老赵那批螺丝退一半，钱先挂着」 | 算 1 次 |
| 没听懂、闲聊、误触、取消 | — | 不算 |

这样定有三个好处：

1. 老板放心说。最常用的那些话都是免费的，不用每说一句就算钱。
2. 成本有上限。真正花钱的只有大模型那部分，而这部分可以按套餐卡住。
3. 方向一致。老板越常用标准说法、越常「教」系统，规则命中越多，你的成本越低，他也越不会撞上额度。

### 2.3 额度用完怎么办（不断服）

- 用到 80% 时提醒一次：「这个月智能理解还剩 20%，可以买加油包」。平时不显示剩余次数。
- 用完以后，规则能懂的照样能记；复杂的句子出一张填空卡，让老板点选或者用数字键盘补，不再调用模型。
- 每个店每天设一个硬上限（比如 200 次，需校准），防止刷量或者程序出错把额度跑空。

### 2.4 账要自己算一遍（公式，所有数都待核实）

```
单店每月 AI 成本 ≈ 每月有效句数 × (1 − 规则命中率) × 单次大模型成本 + 语音转文字费
单店每月毛利   ≈ 套餐价 × (1 − 渠道抽成) − 单店每月 AI 成本 − 分摊固定成本
```

上线前用真实报价把这两行填出来，再反推各档套餐给多少「智能理解」次数。**套餐价和额度都由这两行算出来，不要拍脑袋定。**

## 3. 直接记 vs 出卡，以及「今日流水」

### 3.1 什么时候直接记

**下面全部满足**才直接记。屏幕底部出一行「已记」，旁边带「撤」：

- 进、卖两类（赊、退、盘点、收付款、新货、改单一律出卡）
- 商品唯一对上一件老货，不是猜出来的
- 数量和单位都听到了，单位不用换算，或者换算系数已经有了
- 日期是今天，付款是现结
- 金额在这家店的平常范围内（不超过这件货平常单笔金额的 3 倍，倍数需校准）
- 跟上一笔对比，没有反常（比如刚进了 2 箱，紧接着又说卖 20 箱）

任何一条不满足就出确认卡，只把不确定的那一格高亮。

### 3.2 今日流水（首页主体，就是你说的「每天的记账日志」）

```text
今天 11月20日   卖 ¥1,286   进 ¥420   赊 ¥460         [待处理 3]
─────────────────────────────────────
09:12  进  可乐 2 箱 ¥70           王姐
09:40  赊  李婶 · 烟 2 条 ¥460      王姐   确认过
10:05  卖  冰红茶 3 瓶 ¥12          老公   直接记
10:06  卖  ~~雪碧 1 瓶 ¥3~~         已撤
```

- 每一笔都显示**谁记的、是直接记的还是确认过的**。点开能看到当时说的原话。
- 每一行左滑出「改」「撤」。撤掉的那笔划掉留在原地，不会消失，方便查。
- 收摊时（或订阅消息点进来）有「今天对一遍」：按进、卖、赊分组，一屏看完。看到不对的点一下改，看完点「今天没问题」。这一步不是必须做的。
- 「说清楚了但说错了」（比如把进说成卖），就靠这张流水和收摊对一遍兜底。

### 3.3 不用倒计时

- 确认卡一直留在屏幕上，直到确认、关掉，或者开始说下一句。
- 老板开始说下一句时，上一张卡还没确认，就收起来进「待处理 · 没确认」，同时提示一句「上一笔没确认，先放在待处理」。
- 没确认的卡在待处理里留到第二天，再一并提醒。

## 4 + 8. 缺项与补录：一个机制，两种急迫度

**问不清楚和事后补录用同一个组件，叫「空格」。** 卡片上缺的那一项就是一个空格：上面有可以直接点的选项，下面能用大数字键盘。

| 急迫度 | 哪些项 | 卡片上怎么处理 | 去向 |
|---|---|---|---|
| **必须现在填** | 哪件货（重名时）、数量、进还是卖、「一箱几个」（第一次说到箱） | 空格是红的，这一格没填就点不了确认。可以点「先存着」 | 点了先存着就进 待处理 · 没确认 |
| **可以后补（必补）** | 进价、卖货收了多少、赊给了谁 | 空格是黄的，能确认记账，按钮上写「先记数量，进价待补」 | 进 待处理 · 要补 |
| **不用补** | 规格、供应商（现结时）、备注、条码、分类 | 不出现在卡上 | — |

**哪些项「必补」由系统定死，不让老板自己配**（配置本身就是负担）。上面这张表就是全部。

补录入口只有一个：首页的「待处理」角标。点进去是一张列表，点某一行，弹出的就是同一个空格组件。

## 6. 二次确认

用分级直接记以后，**去掉二次语音确认**。剩下这样分：

| 操作 | 确认方式 |
|---|---|
| 普通进、卖（能直接记的） | 不用确认，有「撤」 |
| 出卡的（赊、退、盘点、新货、改单、有猜测的项） | 点一次大按钮，按钮上写结果 |
| 收付款超过阈值、删除货品、合并客户、导出全部账 | **按住或滑动确认**，按钮上写金额或数量，不念出来 |

## 7. 说话按钮

- **只有一个按钮，不放模式切换。**
- 轻点一下开始说；说完停顿 1 秒左右自动结束（判停时长需真机校准）；想提前结束就再点一下。
- 按住不放也行：说完松手就结束，照顾习惯微信「按住说话」的人。
- 录音时屏幕上**实时出字**，说完立刻显示「在理解…」，卡片再一格一格填出来（对应第 19 条）。
- 时长：逐笔记 15 秒，盘点和开张模式 60 秒。

## 9. 改单：手动和语音都能改，最后都是同一张「改前改后」卡

| 入口 | 例子 |
|---|---|
| 语音 | 「刚才那笔可乐是三箱」「上午那个不是进是卖」「李婶那笔是四百不是四百六」 |
| 手动 | 在流水里左滑那一笔 → 改 → 点要改的那一格 |

两种入口最后都出同一张卡：

```text
改  09:12 进货 · 可乐
数量   2 箱  →  3 箱
金额   ¥70   →  ¥105
库存   现在 10 箱 → 改完 11 箱
[确认改成 3 箱 ¥105]
```

- 改单**一律出卡**，不直接改。
- 语音改的时候，「刚才那笔」默认指自己记的最近一笔。找不到或者有几个都对得上，就列出 2–3 笔让老板点。
- 后台照旧是「反做原单 + 新建更正单」，但老板看到的只是「改好了」，旧值划掉留痕。

## 10. 「待」字头功能精简

| 原来的 | 结论 | 理由 |
|---|---|---|
| 待确认 | **并入** 待处理 · 没确认 | 没有倒计时以后，只剩「放下没确认」这一种情况 |
| 待补 | **并入** 待处理 · 要补 | 核心功能，保留 |
| 待办 / 待审批 | **去掉**（单人店）；有店员时才出现「等老板点头」 | 手机能做全部事情以后，不需要再让电脑审批 |
| 待教学 | **去掉**，变成卡片上的红色空格当场问 | 第一次说「箱」就问一箱几个，答完立刻生效 |
| 候选模板 | **不给用户看**，只在后台运营 | 这是降成本的内部机制，跟老板无关 |

**最后只剩一个入口「待处理」**，里面三种标签：`要补` / `没确认` / `等老板点头`（只有在开了店员时才会有）。

## 13. 信息架构（页面和内容定义）

底部 4 个 Tab，**中间凸起一个说话按钮，每一页都在**。按钮能看懂当前在哪一页：比如在欠款页说「李婶还了 200」，不用说「收款」两个字。

```text
[ 今天 ]   [ 货品 ]   ( 说 )   [ 欠款 ]   [ 我的 ]
```

### 今天（首页）
- 顶部：今天卖、进、赊三个数，右上角「待处理 N」。
- 切换：今天 / 本周 / 本月。一切换，上面的数字和下面的流水一起变。
- 主体：今日流水（3.2）。
- 收摊后在顶部出现「今天对一遍」。
- 倒推模式的店在这里多一张卡：「本周估算卖出 ¥xxx（上次盘点后）」，加一个「去盘点」。

### 货品
- 列表：名字、库存（大字）、单位、进价和售价。缺进价的标黄。
- 上方三个筛选：全部 / 快没了 / 缺进价。
- 右上角「开始盘点」进盘点模式（1.3）。
- 点进一件货：库存、这件货的进出记录、价格历史、叫法（别名）、一箱几个。

### 欠款
- 两个分页：**别人欠我**、**我欠别人**，各显示合计。
- 每个人一行：名字、欠多少、最后一笔是哪天。
- 点进去是这个人的往来明细，底部有两个按钮：「记一笔还款」，以及「**发给他**」，把对账单生成图片，转发到他的微信。

### 我的
- 经营：本月卖了多少、毛利（标明没算哪些缺进价的货）、哪样货卖得最好。
- 店里的人：谁能记、谁能改。
- 说法本（15 节）。
- 记账方式：逐笔 / 倒推。
- 字号：大 / 标准。
- 套餐和用量：只在这里出现。
- 导出全部账（滑动确认，文件转发到微信）。

### 电脑版微信（大屏）
同一个小程序，同样的 4 个页面，**改用表格布局**：
- 货品表能批量补进价、批量设一箱几个。
- 流水表能按日期、类型、谁记的筛选。
- 欠款表能导出。
- 电脑上不用说话，所有操作都能点完。

## 15. 说法本：系统怎么「记住」每个人的说法

### 15.1 先说清楚边界

我们**改不了语音识别模型本身**，没法让它针对某个人的口音重新训练。我们能做的是在**转成文字之后**记住：「这个人说 X，其实是 Y」。效果上一样：下次直接就懂，而且不用再调用大模型。

### 15.2 记成什么样

每一条就是一行映射：

| 字段 | 例子 | 说明 |
|---|---|---|
| 听到的 | 「可了」「快乐水」「拐」「一条」 | 识别出来的原文片段 |
| 其实是 | 可乐 / 可乐 / 7 / 1 条烟 | 标准值 |
| 类型 | 识别错字 / 商品叫法 / 数字读法 / 单位 / 客户叫法 / 句式习惯 | 决定在解析的哪一步用上 |
| 范围 | **个人** 或 **全店** | 口音、错字属于个人；商品叫法、一箱几个属于全店 |
| 怎么来的 | 老板在卡上改过 / 老板说「以后 X 就是 Y」 / 系统发现 | 用于判断可信度 |
| 用过几次、最后一次 | 12 次、11月20日 | 长期不用的自动降权 |

### 15.3 什么时候记、怎么生效

| 情况 | 做法 |
|---|---|
| 老板明确教：「以后快乐水就是可乐」 | 马上生效，范围是全店 |
| 卡上改了一项，比如商品从「可了」改成「可乐」 | 先记下；**同一个人同样改过 2 次**才自动生效，范围是个人 |
| 回答「一箱几个」 | 马上生效，范围是全店，记在这件货上 |
| 两个人对同一个说法映射不同（夫妻俩各叫各的） | 各自的个人映射优先，互不影响 |

### 15.4 老板看得到、管得了

在「我的 → 说法本」里，按「全店」和「我的」分两组列出来，每一条都能删。每条旁边写一句白话，比如「你说『拐』时记成 7」。

如果之后换成支持自定义词表的识别服务，全店的商品名和叫法还会**提前交给识别服务**，在转文字这一步就认对（见第 18 节）。

## 18. 语音转文字：怎么选

### 18.1 两个选项摆在一起

| | 微信同声传译插件 | 付费语音识别服务 |
|---|---|---|
| 钱 | 免费（需核实） | 按次或按时长收费（报价需核实） |
| 配额 | 每个小程序 250 条/分钟、3 万条/天，**所有客户共用**（04 文档写的数，需核实） | 按购买量 |
| 实时出字 | 有 | 多数有（需核实） |
| 每个字的可信度 | **没有**（需核实） | 部分服务有 |
| 自定义词表 | **没有**（需核实） | 多数有，条数有上限 |
| 方言 | 一般（需核实） | 部分服务有方言模型 |

### 18.2 有一笔账要先算清：语音转文字不是大头

按 2.4 的公式，单店成本里大头是大模型那一项。语音转文字的单价通常比大模型低得多（需核实）。

**省下转文字的钱，但让识别更容易出错**，结果是规则更常对不上，就要更多地调用大模型、多问几轮。可能省小钱、花大钱。

还有一个硬限制：插件的配额是**整个小程序共用**的。假设 1000 家店，每家每天说 40 句，就是 4 万句，已经超过每天 3 万条，规模一上来就不够用。

### 18.3 建议：先用插件起步，界面设计不依赖识别可信度

**第一阶段（内测，几十到几百家店）：用同声传译插件。**
- 零成本，实时出字的体验也好。
- 「系统猜的」高亮**不靠识别可信度**，靠我们自己的匹配把握：
  - 商品名完全对上 → 不标；
  - 对上一个，但有错字或用了别名 → 标黄；
  - 有两个都像 → 红色空格，让老板点选。
- 说法本在文字层面纠错（15 节），插件也照样能用。

**第二阶段（快接近配额，或者方言店多）：通过适配层接入付费识别服务。**
- 适配层就是一个转接层，以后换识别厂商不用改上层代码。
- 付费套餐用户优先切换，或者对方言重的店单独切换。
- 有自定义词表以后，把全店商品名和叫法提前注入，转文字这一步就认对。
- 有逐字可信度以后，作为**额外的**判断依据叠加进高亮规则，但不替代第一阶段的匹配逻辑。

**要马上去核实的三件事：**
1. 插件的 3 万条/天配额是不是整个小程序共用，能不能申请提高。
2. 插件能不能同时拿到录音文件。拿得到，以后才能对同一段话「插件没认出来时再交给付费服务重新识别一次」。
3. 目标付费识别服务的真实单价、自定义词表条数上限，以及有没有逐字可信度。

**这样一来，界面设计不用等识别服务定下来**：高亮、空格、说法本这三样，两个阶段都能用。
