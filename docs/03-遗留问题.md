## 三、未关闭 · P2（不阻塞闭环，但会被用户感知）

| # | 问题 | 说明 |
|---|---|---|
| P2-1 | 分钟限流被拒时**仍扣了当日额度** | 已核实：`QuotaService.take()` **先扣日桶再扣分钟桶**（`server/app/services/quota.py:298-334`），分钟限流失败时没有回滚日桶；而接口话术写着「这次没有扣额度」（`server/app/api/v1/voice.py:238-240`）→ 用户发现今天少了一次。改法：先试分钟桶，通过后再扣日桶（或失败时回补） |
| P2-2 | `E_TENANT_DENIED` 把「配置错」和「有人越权」混成一个码 | 前者是运维问题、后者是安全事件，告警处置完全不同 |
| P2-3 | 单号有跳号 | 反做/失败回滚会消耗号段；对账时「号不连续」需要能解释（建议在导出里带一列 `voided`） |
| P2-4 | `is_pure_entity_intent` 名字比语义宽 | 它实际判的是「entities 全落在实体白名单」，会把 R0/R3 也算成纯实体；命名建议改为 `writes_only_entities` |
| P2-10 | 租户扫描器只覆盖 `text()`/f-string 的裸 SQL | SQLAlchemy Core 的 `select()` 拼装绕过扫描（虽然 `TenantRepository` 有 scope，但漏一处就是越权）。建议加 AST 规则 |
| P2-新 | **个人别名不按 `member_id` 过滤** | `load_product_lexicon()` 查 `product_alias` 时只按 `tenant_id`，功能注释却写「个人别名优先生效」→ A 员工教的说法 B 员工也能用，与「个人词表」的产品承诺不符（`server/app/services/voice_runtime.py:115-121`） |
| P2-新 | 词表只装「最近 N 个商品」 | `load_product_lexicon(limit=PROMPT_TOP_PRODUCTS)` 按 `created_at desc` 截断 → 老商品可能不在词表里，语音说它会被判成 `unknown_target`。澄清候选同理。需要「按名字直查兜底」或扩大 limit |
| P2-新 | 反做卡的「影响预览」区域是空的 | 反做方向由 `ReversalService` 自己算，卡片上的 `impact_preview` 没有对应改动行。用户看到「撤销 2 箱」但预览区一片空白。建议用原单行做负数预演 |

## 四、明确「不做」（避免被当成遗漏）

| 项 | 原因 |
|---|---|
| 网页版 / PC Web / H5 / 账号密码登录 | 已定稿：同一 AppID 的微信小程序（手机 + 电脑版微信大屏） |
| 自动续费订阅 | 平台门槛（发布 ≥90 天 + 近 30 天日均 DAU ≥1 万）未达，改一次性购 30 天权益 / 语音加油包 |
| 语音端执行 R3 动作 | 铁律：R3 只能生成待办，执行在电脑版微信大屏 + 老板二次确认 |
| 音频进后端接口 | 音频走 `wx.cloud.uploadFile` 直传对象存储，接口只收 `audio_object_ref` |
