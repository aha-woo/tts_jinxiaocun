# 库存、批次与供应商设计（P0 → P2）

> 目标：把现在的「语音记账 MVP」补成**完整进销存**的底层数据模型。
> 原则：**成本法可配置**（不同行业不同）、**供应商挂在单据**、**一切数量变动都有流水**、**历史数据只读**。
> 状态：设计稿，确认后按 P0 → P1 → P2 实施。

---

## 1. 为什么需要这份设计

现在只实现了主链路：一句话 → 确认卡 → 一张单据（doc_header/doc_line）+ 库存余额（inventory）。
缺三样东西，缺任何一样都做不成完整进销存：

1. **供应商**：现结进货根本不落库（只有赊账通过 ar_ap 间接记录）；
2. **批次与成本**：库存只有「商品×门店=数量」，没有批次、没有成本法，卖货算不出真实毛利；
3. **流水**：没有独立的库存变动表，盘点/报损/调拨这类「无单据变动」无处安放。

结论：先定模型，再写代码。批次一旦上，库存从「一个数」变成「一堆批次」，报表、盘点、成本全部受影响，不能边走边改。

---

## 2. 核心决策（已定 / 待确认）

| 决策 | 结论 |
|---|---|
| 成本法 | **可配置**：租户默认 + 商品可覆盖；支持 FIFO / FEFO / 移动平均 |
| 负库存 | **待确认策略**：禁止（默认）/ 允许并标记 / 按门店放开 |
| 历史数据 | **只读**，新单开始生效；不回填供应商、不补批次 |
| 供应商位置 | `doc_header.partner_id`（单据级唯一事实）；商品档案只放「默认供应商」做输入便利 |
| 一单多供应商 | 不支持（评审结论） |
| 批次成本 | 入库批次记成本；出库按成本法分摊；移动平均用汇总成本 |

## 3. 数据模型

### 3.1 新增/修改表

```sql
-- ① 单据头加供应商/客户（现结也写）
ALTER TABLE doc_header ADD COLUMN partner_id UUID NULL;   -- → partner.partner_id
CREATE INDEX ix_doc_header_partner ON doc_header(tenant_id, partner_id, biz_date);

-- ② 库存策略（租户级默认，可被商品覆盖）
CREATE TABLE inventory_policy (
  tenant_id      UUID PRIMARY KEY,
  cost_method    TEXT NOT NULL DEFAULT 'fifo',   -- fifo | fefe | avg
  allow_negative BOOLEAN NOT NULL DEFAULT FALSE,
  updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- ③ 商品可覆盖成本法
ALTER TABLE product ADD COLUMN cost_method TEXT NULL;  -- NULL = 跟随租户

-- ④ 入库批次
CREATE TABLE stock_batch (
  batch_id      UUID PRIMARY KEY,
  tenant_id     UUID NOT NULL,
  store_id      UUID NOT NULL,
  product_id    UUID NOT NULL,
  doc_line_id   UUID NOT NULL,          -- 哪一行进货进来的
  partner_id    UUID NULL,              -- 供应商（冗余，便于按供应商追溯）
  qty_in        NUMERIC(18,4) NOT NULL, -- 入库数量（base unit）
  qty_left      NUMERIC(18,4) NOT NULL, -- 剩余数量，出库时扣减
  unit_cost_fen BIGINT NOT NULL,        -- 批次单位成本（分）
  prod_date     DATE NULL,
  expiry_date   DATE NULL,              -- FEFO 依据
  received_at   TIMESTAMPTZ NOT NULL,
  status        TEXT NOT NULL DEFAULT 'open',  -- open | exhausted | adjusted
  UNIQUE (tenant_id, doc_line_id)
);
CREATE INDEX ix_batch_pick ON stock_batch(tenant_id, store_id, product_id, status, expiry_date, received_at);

-- ⑤ 库存流水（唯一数量变动账本）
CREATE TABLE inventory_movement (
  move_id       UUID PRIMARY KEY,
  tenant_id     UUID NOT NULL,
  store_id      UUID NOT NULL,
  product_id    UUID NOT NULL,
  batch_id      UUID NULL,              -- 移动平均/盘点汇总时可为空
  doc_id        UUID NULL,              -- 盘点调整/报损可以没有单据
  reason        TEXT NOT NULL,          -- purchase|sale|count_adjust|loss|transfer_in|transfer_out|opening
  qty_base      NUMERIC(18,4) NOT NULL, -- 正=入，负=出
  unit_cost_fen BIGINT NULL,            -- 出库分摊后回填（FIFO/FEFO）
  partner_id    UUID NULL,
  occurred_at   TIMESTAMPTZ NOT NULL,
  created_by    UUID NOT NULL
);
CREATE INDEX ix_move_query ON inventory_movement(tenant_id, store_id, product_id, occurred_at);
CREATE INDEX ix_move_doc ON inventory_movement(tenant_id, doc_id);

-- ⑥ 盘点
CREATE TABLE count_session (
  count_id    UUID PRIMARY KEY,
  tenant_id   UUID NOT NULL,
  store_id    UUID NOT NULL,
  status      TEXT NOT NULL DEFAULT 'open',  -- open | submitted | applied | cancelled
  started_by  UUID NOT NULL,
  started_at  TIMESTAMPTZ NOT NULL,
  applied_at  TIMESTAMPTZ NULL
);

CREATE TABLE count_line (
  count_line_id UUID PRIMARY KEY,
  tenant_id     UUID NOT NULL,
  count_id      UUID NOT NULL,
  product_id    UUID NOT NULL,
  qty_book      NUMERIC(18,4) NOT NULL,  -- 账面数（打开盘点时快照）
  qty_counted   NUMERIC(18,4) NULL,      -- 实盘数；NULL = 没数
  reason        TEXT NULL                -- sold|lost|wrong 等，勾选解释
);
```

### 3.2 关系

```
partner ──< doc_header ──< doc_line ──< stock_batch（入库时一行一批）
   │             │
   │             └──< inventory_movement（doc_id 可空）
   └──< ar_ap（赊账时）
product ──< stock_batch / inventory_movement / count_line
inventory（余额表）保留：商品×门店 → qty_base，由 movement 汇总校验
```

## 4. 写入规则（关键：什么时候写什么）

### 4.1 进货确认（purchase.*）

1. 写 doc_header（带 `partner_id`）+ doc_line；
2. `inventory.qty_base += qty_base`；
3. 对该单每一行建 `stock_batch`（`qty_in=qty_left=qty_base`，`unit_cost_fen` 取单据单价）；
4. 写 `inventory_movement(reason=purchase, qty_base=+, batch_id)`；
5. 赊账照旧写 ar_ap。

### 4.2 卖货确认（sales.*）

1. 依据成本法取批次（见 §5），逐批扣 `qty_left`；
2. 每个批次写一条 `movement(reason=sale, qty_base=-, batch_id, unit_cost_fen=该批成本)`；
3. 汇总销售成本（COGS）写入 doc_header（新增 `cogs_fen` 字段）；
4. 库存余额扣减；
5. 负库存处理见 §6。

### 4.3 反做（撤销/更正）

原单反做时：

- 写反向 movement（reason 继承原 reason，qty 取反）；
- 进货反做：批次 `status=adjusted`（余量不动，靠反向 movement 平账）；
- 卖货反做：把卖出的量按原批次退回 `qty_left`；
- 更正单再按 4.1/4.2 正常写。

### 4.4 盘点（P1）

- 打开盘点：对每个商品快照 `qty_book`；
- 提交：计算差异 = 实盘 − 账面；
- 应用：写 `movement(reason=count_adjust, qty_base=差异)`，按成本法调整批次余量（FIFO 扣/补最近批次），不改历史单据。

### 4.5 报损、调拨（P2）

- 报损：`movement(reason=loss, qty_base=-)`，按成本法扣批次；
- 调拨：出库 `transfer_out` + 入库 `transfer_in`，批次随货转移（保留成本）。

## 5. 成本法：可配置（FIFO / FEFO / 移动平均）

### 5.1 配置层级

```
product.cost_method（优先，NULL 表示跟随）
  ↓
inventory_policy.cost_method（租户默认）
  ↓
fifo（系统兜底）
```

- 设置入口：我的 → 库存设置（租户默认）；商品详情 → 成本法（覆盖）；
- 改配置**只影响之后的出库**，不重算历史（与 06 文档口径一致）。

### 5.2 三种算法

| 方法 | 取批顺序 | 成本 | 适用 |
|---|---|---|---|
| FIFO | `received_at` 升序 | 按批次实际成本 | 标品、价格稳定、普通批发 |
| FEFO | `expiry_date` 升序（空值排后） | 按批次实际成本 | 食品、药品、临期品 |
| 移动平均 | 不按批次分摊 | 平均成本 = 当前库存金额 / 数量 | 大宗、价格波动大、不想管批次 |

移动平均仍写批次（追溯用），但成本按均价；出库时 `unit_cost_fen` 取均价。

### 5.3 缺批次数据时

- 可用批次不足（历史单据没有批次）→ 出库按「商品最近进价」兜底，并写一条 `pending_cost` 标记，出现在「要补」里；
- 该行为可配置：严格模式（不足就拒卖）。

## 6. 负库存：现实里是什么

**不是"欠供应商"**。欠供应商是 `ar_ap`（应付），是钱；负库存是**数量**——账上比实际少了。

真实发生场景：

1. **先卖后补录**：货实际在，但进货单还没录，先卖了 → 账上负数；
2. **代销/寄售**：货不是买断的，卖了再结算；
3. **盘点前被动出库**：上次盘点后没补进货单；
4. **跨店调拨未到**：货在路上，源店先扣。

风险：负库存时**没有批次可扣**，成本算不出来（毛利失真），也无法追溯来源。

策略（建议三选一，默认 A）：

| 策略 | 行为 |
|---|---|
| A. 禁止（默认） | 出库前校验可用量，不足就拒绝，提示"库存不足，先记进货" |
| B. 允许并标记 | 允许卖，movement 记负数，商品进「负库存」待办，补进货后自动回填 |
| C. 按门店放开 | 允许部分门店（如先卖后补的档口）负库存，其他店禁止 |

配置项：`inventory_policy.allow_negative`，P1 做 B/C 的完整回填逻辑，P0 先默认 A。

## 8. 迁移与兼容

1. **新增表/列用 Alembic 迁移**，全部可空或带默认值，不锁表；
2. 历史单据：`partner_id` 保持 NULL、无批次、无 movement（只读）；

5. 现有测试守卫（只有 ledger/reversal 写单据）保留；新写路径（movement/batch）也只在 ledger/reversal 内调用。

## 9. 验收（每阶段）

**P0**
- 进货（现结）落库后 `doc_header.partner_id` 有值；
- 每张单据产生对应 movement；`SUM(movement)=inventory`；
- 扣掉所有历史单据后，对账任务一致；
- 单测：进货/卖货/反做三种 movement 方向正确。

**P1**
- 进货建批次，卖货按 FIFO/FEFO 扣批次，COGS 正确；
- 切换成本法只影响后续出库；
- 盘点差异写 count_adjust movement，余额与批次一致；
- 负库存策略 A 下，超卖被拒并给出可照做的提示。

**P2**
- 报损、调拨有流水、可追溯；
- 按商品查供应商、按批次查来源、毛利报表可用；
- 批次追溯：一个卖单能追到具体进货批次和供应商。

## 10. 实施顺序与风险

| 阶段 | 内容 | 主要风险 |
|---|---|---|
| **P0** | 供应商字段 + movement 表 + 落账双写 + 对账校验 | 双写一致性（必须同事务） |
| **P1** | 批次表 + 成本法（fifo/fefe/avg）+ 盘点 | **高**：库存从数量变批次，报表/盘点/成本全改 |
| **P2** | 报损、调拨、追溯报表、毛利 | 中：报表口径要统一 |

**不建议**跳过 P0 直接做批次：没有流水和供应商，批次做了也追不到来源，对账仍然缺一条腿。
