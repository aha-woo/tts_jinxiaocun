## 1. 决策类问题（不是 bug，是选型）

### 1.1 云开发 PG 模式环境「暂时不支持小程序原生使用」

- **官方口径**（社区 [#1792](https://cnb.cool/tencent/cloud/cloudbase/community/-/issues/1792)）：PG 环境暂不支持小程序端数据面，IDE 里也选不到该环境。
- **对本项目的影响：很小**——小程序从不直接读数据库，只用 `callContainer` 调云托管。
- **真正要确认的是另外两件事**：① 该环境能否开通云托管；② 云托管容器能否直连 PG。两条都实测通过。
- **结论**：PG 模式环境可用，但**必须走「云托管 + 同环境内网直连」**，不要指望小程序端直连。

### 1.2 不需要「小程序 B」

- 主体是**企业法人**，虚拟支付资格没有障碍；
- 插件、隐私指引、备案、认证全部**按 AppID 走**，换云开发环境不受影响；
- 只有当主体是「个人」、又想收订阅费时，才必须新注册企业主体小程序（个人主体不可变更）。

### 1.3 共享集群 vs 独享集群

- **免费体验版 = 共享集群**：控制台的「内网地址 / 外网地址 / SSL / 安全组」全是 `-`，tooltip 原话是「当前共享集群暂不提供相关能力，可以升级至独享集群启用能力」。
- 想拿到 PG 连接地址，**必须升级到标准版并把 PG 升级为独享集群**（不可回退）。
- 独享计费按「分配规格 × 运行时长」，**不开请求也扣点**：1 核 2G + 10GB ≈ 347 资源点/小时 ≈ 25.3 万点/月。

## 2. 部署链路上的 7 个坑（按出现顺序）

### 2.1 环境变量没进容器 → 启动即被自检拦下

**现象**

```
RuntimeError: 生产配置自检未通过，拒绝启动：
- DATABASE_URL 不是 PostgreSQL（dialect='sqlite'）
- WX_PROVIDER='fake'
- JWT_SECRET 仍是本地默认值
```

**根因**：云托管的环境变量是**版本级快照**。在服务设置里加完不重新部署，旧版本容器里还是空的。

**修复**：服务设置 → 环境变量 → 保存 → **重新部署**（不是「重启」）。

**判据**：日志里 `[boot] ... db_url_set=yes migration_url_set=yes`。

---

### 2.2 容器监听 80 → 非 root 绑不了 → CrashLoop 且无日志

**现象**

```
Back-off restarting failed container
Readiness probe failed: dial tcp 10.7.12.48:8080: connect: connection refused
```

「启动日志」为空。

**根因**：镜像 `USER appuser`（uid 10001），K8s 默认禁止非 root 绑 1024 以下端口。本地 Docker 能跑是因为 Docker 放开了这个限制——**所以本地永远发现不了**。

**修复**：`PORT=8080` / `EXPOSE 8080` / CMD `--port ${PORT:-8080}`；云托管里「服务端口」填 **8080**（访问端口 80）。

**判据**：日志出现 `INFO: Uvicorn running on http://0.0.0.0:8080`。

---

### 2.3 PG 没开 SSL → `server does not support SSL`

**现象**

```
psycopg.OperationalError: ... failed: server does not support SSL, but SSL was required
```

**根因**：连接串写了 `sslmode=require`，但实例的「强制执行传入连接的 SSL」是关的。

**修复**：PG 控制台 → SSL 配置 → 打开「强制执行传入连接的 SSL」，重启版本即可，**连接串不用改**。

**要澄清的一个误区**：`sslmode=require` **不需要下载证书**。那个「下载证书」是给 `verify-ca` / `verify-full` 用的（要配 `sslrootcert`）。内网 `require` 足够。

---

### 2.4 账号密码对不上 → `password authentication failed`

**现象**

```
FATAL: password authentication failed for user "root_postgres-e7d47gcm"
```

**根因**（多重）：

1. 控制台「数据库密码」重置的**未必是**你想用的那个账号；
2. 密码含 `!` 等特殊字符，URL 里没做百分号编码；
3. 环境变量里粘进了空格/换行。

**修复**：不要在不知道密码的账号上纠缠，**直接用 SQL 编辑器把密码设成自己知道的值**：

```sql
ALTER ROLE vil WITH PASSWORD 'Vil_<16位hex>';
ALTER ROLE vil WITH NOSUPERUSER NOBYPASSRLS;
```

**经验**：密码优先用「大写 + 小写 + 数字 + 下划线」这种**不需要 URL 编码**的组合；必须用特殊字符时，用下面这条命令整体编码：

```powershell
python -c "import urllib.parse; print(urllib.parse.quote('原始密码', safe=''))"
```

---

### 2.5 `permission denied for database` → 干脆建独立库

**现象**

```
FATAL: permission denied for database "postgres"
DETAIL: User does not have CONNECT privilege.
```

**根因**：`vil` 能通过密码认证，但 CloudBase 收紧了 `postgres` 库的 `PUBLIC CONNECT`；而 SQL 编辑器的身份不一定有权限 `GRANT CONNECT`。

**修复**（一步到位）：给项目建独立库，让 `vil` 当 owner：

```sql
CREATE DATABASE vil OWNER vil;
```

然后把两段 URL 的库名从 `postgres` 改成 `vil`。owner 天然拥有 CONNECT + 建表 + 建策略权限，也顺带跟平台库隔离。

> 如果 `CREATE DATABASE` 报「不能运行在事务块里 / 权限不足」，改用控制台 UI「数据库管理 → 新建数据库」。

---

### 2.6 迁移在容器里找不到契约文件

**现象**

```
app.config.ContractError: 契约文件缺失: /packages/shared/contracts/intents.json
```

**根因**：镜像把 `server/app` 拷到 `/app/app`，`load_contracts()` 按 `__file__` 反推仓库根得到 `/`，默认路径变成 `/packages/shared`；而镜像实际把契约放在 `/app/packages/shared`（Dockerfile 已设 `CONTRACTS_DIR`）。**迁移调用 `load_contracts()` 时不传参，忽略了环境变量。**

**修复**：`app/config.py::load_contracts` 的目录优先级改为：

```
显式参数 → 环境变量 CONTRACTS_DIR → 仓库内默认路径
```

并加回归测试 `test_load_contracts_honours_contracts_dir_env`。

---

### 2.7 网络不通时迁移无限等 → 「等待 pod 就绪」卡 20 分钟

**现象**：部署一直「创建中」，没有任何日志。

**根因**：`migrations/env.py` 建连没有超时，psycopg 默认 `connect_timeout=0`（无限等）。

**修复**：迁移的在线模式加 `connect_args={"connect_timeout": 5}`（SQLite 分支不加）。**5 秒内失败并把原因打进日志**，而不是让平台干等。

## 3. 诊断手段：`[boot]` 体检日志

云托管在容器 CrashLoop 时经常**不显示 Python traceback**，「启动日志」一片空白。所以在 CMD 最前面打点：

```
[boot] pid=1 port=8080 migration_url_set=yes db_url_set=yes
[boot] running alembic upgrade head
[boot] alembic done
[boot] starting uvicorn
```

**读法**：

| 缺哪行 | 说明 |
|---|---|
| 一行 `[boot]` 都没有 | 平台没执行我们的 CMD（启动命令被覆盖 / 镜像问题） |
| `migration_url_set=` 为空 | 环境变量没注入到该版本 |
| 停在 `running alembic` + traceback | 数据库连接 / 权限 / SSL 问题，紧跟的那行错误就是答案 |
| 有 `starting uvicorn` 但探针仍拒绝 | 端口 / 绑定问题 |

## 4. 环境变量清单（8 条）

```ini
APP_ENV=prod
DATABASE_URL=postgresql+psycopg://vil:<密码>@172.17.0.13:5432/vil?sslmode=require
MIGRATION_DATABASE_URL=postgresql+psycopg://vil:<密码>@172.17.0.13:5432/vil?sslmode=require
JWT_SECRET=<64 位随机>
WX_PROVIDER=real
WX_APPID=wx5f8449151a641954
WX_APP_SECRET=<mp 后台 AppSecret>
SERVICE_TOKEN=<64 位随机>
```

要点：

- `MIGRATION_DATABASE_URL` 存在时，容器启动会先跑 `alembic upgrade head`，失败即退出（不带病接流量）；
- 两条 URL 里的库名必须是 **`vil`**（不是 `postgres`）；
- 值不要加引号、前后不要有空格/换行；
- `SERVICE_TOKEN` 之后要与「发货云函数」里配置的值**完全一致**。

```
[ ] 1. 日志出现：Running upgrade ... 0003_fix_rls_empty_guc

[ ] 3. GET /healthz  → status ok
[ ] 4. GET /readyz   → dialect=postgresql / tables=34 / isolation_mode=db_rls / degraded_reasons=[]
[ ] 5. 容器终端：python scripts/probe_env.py → 6 项全绿
[ ] 6. 小程序首页自检 → 「后端正常」+ 契约 38/18/25
```

`probe_env.py` 的 6 项里，最容易忽略但最关键的是**第 6 项：应用账号不是超级用户**——超级用户会绕过 RLS，用 `root_postgres-*` 跑应用等于隔离白做（真 PG 上实测过：跨租户可互看）。

## 7. 速查表（症状 → 去哪改）

| 症状 | 最可能原因 | 处理 |
|---|---|---|
| `Back-off restarting` + 启动日志为空 | 端口 80 非 root / 启动命令被覆盖 | 服务端口改 8080；启动命令留空 |
| `[boot]` 一行都没有 | 平台没跑我们的 CMD | 清空启动命令设置 |
| `migration_url_set=` 空 | 环境变量没进版本 | 保存后**重新部署** |
| `server does not support SSL` | 实例没开 SSL | 开「强制执行传入连接的 SSL」 |
| `password authentication failed` | 密码/编码/账号不对 | SQL 编辑器 `ALTER ROLE ... PASSWORD` |
| `permission denied for database` | 没 CONNECT | 建独立库 `vil OWNER vil`，URL 改库名 |
| `permission denied for schema public` | 建表权限 | `GRANT USAGE, CREATE ON SCHEMA public TO vil` |
| `契约文件缺失: /packages/shared/...` | 没读 `CONTRACTS_DIR` | 用 `74e288b` 之后的镜像 |
| 部署一直是「创建中」 | 迁移建连无超时 | 用 `016c9ec` 之后的镜像 |
| 小程序调用 404 / 服务找不到 | `X-WX-SERVICE` 与服务名不一致 | 改 `miniprogram/services/api.ts` 的 `CLOUD_SERVICE` |
| 小程序调用不通但服务正常 | `CLOUD_ENV` 不是本环境 | 改 `api.ts` 的 `CLOUD_ENV` |

## 8. 遗留事项（按优先级）

1. **插件后台两件事**：② 「用户隐私保护指引」声明麦克风；③ 插件版本与 `app.json` 逐字核对 —— 不做，真机语音点不动。
2. **P0-1 续费发货时区崩溃**：`entitlement.valid_from/valid_until` 是 naive 时间，第二次购买同一档位会 `TypeError`。
3. **P0-2 付费额度不生效**：发货写进 `entitlement.remaining`，但没有任何代码消费它，`/usage` 只显示 `usage_quota.free_quota`。
4. **R3 审批后的执行入口**：`POST /tasks/{id}/approve` 只改状态，换算系数永远批不了 → 「1 箱 = 24 瓶」学不会。
5. 导出文件生成（当前 `signed_url` 是 `local-signed://` 假地址）。
6. 密码/密钥轮换（部署过程中有密钥出现在聊天记录里，建议重置 AppSecret、JWT_SECRET、SERVICE_TOKEN）。

## 9. 一句话总结

> 这次卡了 7 个点，**没有一个是业务代码问题**，全是「本地与容器/云环境的差异」：
> 端口权限、环境变量快照、SSL、账号权限、容器路径、网络超时、构建上下文。
> 跑通一次之后，这些差异都已被写进镜像和文档，下次部署应当是一次过。
